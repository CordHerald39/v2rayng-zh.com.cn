> 2026-10-04 来源核验：本文依据官方资料独立整理，未执行客户端 GUI、真实节点或设备实测。文中的验收步骤是操作建议。

## “启动”曾经容易被读成打开应用
2.3.10 预发布记录包含启动自动连接设置改进。关联 PR #6179 说明，原先的设置控制设备启动广播，并非每次打开应用就连接。新标签强调设备开机后的连接，同时提醒 Android 可能限制后台启动；这次改动没有新增独立的“应用打开即连接”行为。

## 系统 VPN 入口也不是自动开关
该 PR 增加系统 VPN 设置入口，在系统提供对应处理器时显示。点击后打开 Android 的 VPN 设置页，不会自动打开“始终开启 VPN”，也不会替你改变系统设置。某些设备没有可用入口时，该项可能不显示。
因此，应先确认你的目标：设备重启后尝试连接，还是由系统维持始终开启的 VPN。二者管理位置与行为不同，不能仅凭应用中的开关颜色判断系统状态。

## 在自己的设备上分开核验
先记录系统版本、客户端版本、当前选择的配置及现有系统 VPN 设置。检查手动连接是否可用，然后再改变需要的自动连接项。
对开机连接，用一次正常设备重启确认客户端是否启动服务，并记录网络建立前后的状态。对系统始终开启，进入系统设置核对选中的 VPN 应用及相应选项；不同厂商界面可能不同。不要同时更改电池策略和全部自动连接设置，先观察具体失败阶段。

## 失败报告需要什么
| 信息 | 为什么需要 |
| --- | --- |
| 设备重启还是仅打开应用 | 区分触发事件 |
| Android 与客户端版本 | 区分系统与界面差异 |
| 系统 VPN 选项状态 | 判断是否由系统管理 |
| 手动连接结果与日志 | 排除配置本身不可用 |
上游 PR 的模拟器结果不能当作本站的设备实测，更不能证明所有厂商后台策略都一致。稳定版 2.2.6 用户也不能直接要求看到预发布版新增标签。本文没有执行设备重启或系统 VPN 设置测试。
